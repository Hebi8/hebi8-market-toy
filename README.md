# hebi8 外汇回放 · Toy

一个 Bilibili Toy：把历史上日元大波动的那几个小时，按 1 分钟线一根一根放出来，用虚拟的 100 万日元边看边买卖，结束时结算。品种是 USD/JPY、EUR/JPY、AUD/JPY，共 12 个场景。

整个包是静态文件，行情数据随包，运行时不请求任何站外地址。

## 本地预览

需要 Node.js 22+、python3（解压数据和打 zip 用）。

```bash
npm install
npm run dev
# 手机通过局域网访问：
HOST=0.0.0.0 npm run dev
```

- 三种尺寸切换（桌面 / 手机全屏 390×844 / 视频下方半屏 360×400）：`http://127.0.0.1:8818/preview.html`
- 页面本身：`http://127.0.0.1:8818/toy/hebi8-fx-preview/index.html`
- `PORT` 可换端口。`npm run dev -- --dist` 改为原样提供 `npm run build` 的产物。

预览不模拟 B 站容器：账号、云存档、排行榜只有在 Toy 里才有，本地用 localStorage 和「本机最好成绩」代替。

## 玩法和规则

所有可调的数字都在 [`src/engine/rules.js`](src/engine/rules.js)：`RULES` 是会影响结果的（初始资金、杠杆、每手单位、点差、强平线、最小手数），`REPLAY` 只影响显示和操作（周期、倍速、显示时区）。规则页的文字是从这些常量生成的，改了常量不用再改文案。

| 项目 | 默认值 |
| --- | --- |
| 初始资金 | 1,000,000 日元（虚拟） |
| 杠杆 | 25 倍 |
| 1 手 | 10,000 单位基础货币，最小 0.1 手 |
| 点差（固定） | USD/JPY 0.3 点、EUR/JPY 0.5 点、AUD/JPY 0.6 点（1 点 = 0.01 日元） |
| 强平线 | 维持率 100% |
| 按杠杆下单的快捷档 | 本金的 1× / 5× / 10× / 最大 |
| 周期 | 1 分 / 5 分 / 15 分，由 1 分钟线聚合 |
| 倍速 | 每秒 1 / 2 / 5 / 10 / 30 根 1 分钟线，每局从 1× 开始 |

- 选好场景和品种，进去就以 1× 自动播放；「继续上一局」回来时是暂停的。
- 图上画的是买价（bid）。买入按买价加点差成交、按买价平仓；卖出按买价成交、按买价加点差平仓。
- 仓位大小用**实际杠杆**表达：持仓的日元价值 ÷ 当前净值（多单和空单相加，不抵消）。下单区写的是「这一单 ≈ 本金的几倍 · 下单后合计几倍（上限 25 倍）」，快捷档按倍数换算成手数（向下取整到 0.1 手，不低于最小手数，不超过保证金允许的最大手数），账户栏和每笔持仓也都标倍数。这只是展示和下单方式，规则没变。计算在引擎里（`summary().leverage`、`orderLeverage`、`positionLeverage`、`lotsForLeverage`）。
- 保证金在开仓时定下：开仓价 × 数量 ÷ 杠杆。维持率 = 净值 ÷ 已用保证金。这几项在账户栏里排在净值、浮动盈亏、实际杠杆后面。
- 止损、止盈在下单时按「距开仓价多少点」填写，可以不设。可以同时持有多笔，可以做空，「全部平仓」一键平掉。
- 维持率跌破强平线时强制平仓：从亏损最大的一笔开始平，直到维持率回到线上；如果所有仓位都被强平，本局结束。
- 回放放完时，没平的仓位按最后一个价格平掉再结算。也可以提前「结算」（要点两次）。没有任何交易的一局不计成绩。
- 无论图表切到哪个周期，成交和判定都按 1 分钟线进行；「单步」前进一根当前周期的 K 线。

### 一根 K 线里的判定顺序

一根 K 线只有开、高、低、收，不知道高和低谁先谁后。引擎（[`src/engine/engine.js`](src/engine/engine.js) 的 `step`）按**对玩家不利**的顺序走：

1. 假定价格的路径是：开盘 → 对账户净持仓不利的那一端（净多头先到最低，净空头先到最高）→ 另一端 → 收盘。
2. 沿这条路径，哪个价位先碰到就先执行哪个：某一笔的止损，或者让维持率跌破强平线的那个价格（净值随价格线性变化，这个价格可以直接解出来，并向不利方向取整）。
3. 止盈只在走完这条路径之后才看，而且只看还活着的仓位。所以**同一根 K 线里止损和止盈都被碰到时，一律算止损**；强平和止盈同时可能时，算强平。
4. 跳空：K 线开盘时已经越过止损或强平线的，按开盘价成交（比设定的价格更差）。止盈永远只按设定的价格成交，不会更好。
5. 空头的止损、止盈按卖价（买价 + 点差）判断。
6. 最大回撤按净值在这条路径上的最低点计算，不只是收盘时。

这些规则都有单元测试（[`test/engine.test.js`](test/engine.test.js)）。

### 结算页

最终净值、收益率、最大回撤、交易次数、盈利笔数、最好和最差的一笔，以及同一段行情下的两个对照：1 倍杠杆买入持有（开局用全部本金买入、不加杠杆、拿到最后，也就是价格本身的涨跌减去点差），和不动（0%）。

### 涨跌配色

默认绿涨红跌（国际惯例）：K 线、买入／卖出按钮、盈亏数字、多空标记、图上的持仓线全部跟着走，涨、盈利、买入是一种颜色，跌、亏损、卖出是另一种。首页品种选择的右边可以切成红涨绿跌，选择会记住。两种颜色只写在 [`src/theme.js`](src/theme.js) 一处：样式表通过它设置的 `--up` / `--down` 等变量取色，图表也从它取；`npm run check` 会拦住写在别处的涨跌颜色。

## 数据

- 来源：[HistData.com](https://www.histdata.com/) 免费提供的「Generic ASCII · M1」历史报价（买价），按品种、按年一个 zip。
- 粒度：1 分钟。没有报价的分钟在文件里就不存在，这里也不补。
- 处理后的场景文件在 `public/data/`（36 个文件加一个索引，共约 0.5 MB），随仓库提交；原始 zip 在 `raw/`（约 91 MB，不提交）。

### 重新抓取和生成

```bash
npm run data:fetch   # 按 scripts/scenarios.mjs 需要的年份下载到 raw/histdata/，已有的跳过
npm run data:build   # 生成 public/data/
```

`data:fetch` 走的就是网站自己的下载表单：读年份页里的令牌，再提交表单；一次一个文件，中间停几秒，遇到任何异常就停下，不重试、不并发。当年（未结束的年份）在网站上是按月分的，脚本只处理已结束的年份。

### 时间戳是怎么校正的

HistData 说它的时间是「不带夏令时的美东标准时间」，实际文件不是这样，而且新旧年份还不一样。`scripts/histdata.mjs` 的做法：

- 两种可能的时钟：纽约当地时间（旧年份），或者换成欧洲夏令时切换日的 UTC−5 / UTC−4（新年份）。外汇市场每周在纽约时间周五 17:00 收盘、周日 17:00 开盘，而美国和欧洲的夏令时不在同一个周日切换，所以用错时钟时，一年里总有几周会在 17:00 之前开盘或之后收盘。每个年份文件必须恰好只有一种时钟能通过全部周末，否则报错。结果：2008–2016 是纽约时间，2019–2024 是欧洲切换日。
- 文件在冬令时切换的那个周日会把某一个小时原样重复一遍，读取时去掉完全相同的重复行；出现不相同的时间倒退则报错。
- 有明确发生时刻的场景在 `scripts/scenarios.mjs` 里带一个 `anchor`（比如 2011-10-31 日本时间 10:25 的干预）。生成数据时会检查：这个时刻前后三小时内波动最大的一分钟，必须落在它上面。
- 另外用同一天的另一份数据核对过：2022-09-22 的 USD/JPY，1431 根 1 分钟线和 Dukascopy 按 UTC 记录的同一天逐根完全相同。

## Toy SDK

SDK 只在 B 站域名下加载（[`src/toy.js`](src/toy.js)），每个接口先用 `isSupport` 探测，失败一律回退，不影响游戏：

- `onContainerChange`：安全区写进 CSS 变量 `--toy-safe-*`。
- `setCloudStorage` / `getCloudStorage`：每个「场景 × 品种」的最好成绩（键 `hebi8fx_best_v1`，和本地的合并，取高的），以及跟着人走的设置（键 `hebi8fx_settings_v1`，现在只有涨跌配色；云端有就以云端为准）。没有云存档时只用 localStorage。进行中的一局只存在本地，可以在场景列表「继续上一局」。
- `submitScore` / `getRankList` / `getMyRank`：一个榜（board 1），分数是单局收益率 × 100 的整数（SDK 只收 ±2²⁴ 以内的整数）。没有排行榜时结算页和排行榜页只显示本机最好成绩。榜单返回的字段没有文档，读取时按常见字段名取，取不到就当没有榜。

- `navigate`：首页底部和结算页的「作者主页」，`toy.navigate({ type: "space", id: "66384529" })`；没有 SDK 时（本地预览、普通浏览器）新开 `https://space.bilibili.com/66384529`。这是包里除 SDK 以外唯一的地址，`npm run check` 的允许名单里只有这两个。

没有用到 `getUserProfile`，没有第三方统计、B 站以外的链接、联网字体。
